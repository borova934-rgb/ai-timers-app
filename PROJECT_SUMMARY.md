# AI Timers: История и архитектура проекта

В этом документе описан полный процесс разработки, настройки и функционал приложения "AI Timers", включая этапы веб-разработки и портирования на Android.

## 1. Концепция и Базовый Стек
Изначально была поставлена задача создать трекер кулдаунов для нейросетей, где каждый аккаунт отслеживает несколько лимитов времени.
- **Стек технологий:** React + Vite (JavaScript).
- **Стилизация:** Чистый CSS с использованием современных эффектов (Glassmorphism, полупрозрачные карточки, backdrop-filter), что позволило разработать premium-интерфейс в духе iOS.
- **Развертывание на Android:** CapacitorJS + автоматизированная облачная сборка через GitHub Actions.

## 2. Разработка Пользовательского Интерфейса (UI/UX)
Большое внимание было уделено эстетике приложения. Вопреки стандарту, мы не использовали тяжелые UI-библиотеки, а создали собственную адаптивную дизайн-систему:
- **Переключатель тем (Light, Dark, Cream):** Умная смена цветовых `CSS-переменных` (`--bg-color`, `--panel-bg`, `--accent` и т.д.) позволяет мгновенно менять весь облик приложения по нажатию кнопки. Хранится в `localStorage`.
- **Карточки аккаунтов (PositionCard):** iOS-стиль с плавными тенями и скруглениями:
  - Умный "заголовок" карточки с бейджами (Тип аккаунта, Страна).
  - Красивые прогресс-бары с плавной анимацией (`transition: width 1s linear`), которые меняют цвет с оранжевого на зеленый по мере заполнения.
- **Выбор времени (iOSDateSelect):** Стандартные `<select>` на Android выглядят громоздко. Мы решили эту проблему, интегрировав библиотеку `react-mobile-picker`. В результате у нас получился невероятно красивый и понятный 3D-iOS-барабан прямо на любой платформе.
- **Всплывающие окна (Add/Edit Modal):** Стильные модальные элементы поверх размытого фона (Blur) с логикой защиты случайных нажатий.

## 3. Ядро и Расчет Времени (Time Logic)
Самое сердце приложения — утилита `utils.js` и структура `getSortScore`:
- Парсинг точных US-дат: Мы обрабатываем скопированные строки (напр., `04/06/2026 04:02:01 PM`) с учетом того, что таймеры должны быть строго привязаны к московскому времени (МСК).
- **Умная Ручная Регулировка (Overrides):** Если аккаунт используется не на 100%, мы позволяем вручную обнулять и выставлять лимит от 20% до 100% (шагами по 20% через удобные кнопки + и -), но только если таймер уже свободен (иначе кнопка недоступна).
- **Интеллектуальная сортировка аккаунтов:** В `App.jsx` реализована сложная логика сортировки:
  1. Чем больше "готовых" (обнуленных и сброшенных) таймеров в аккаунте, тем *выше* он в списке.
  2. Если количество обнуленных совпадает — приоритет отдается аккаунтам, чье время ожидания до завершения следующего таймера короче.
  3. Таймеры, которые выключены в настройках (например, Claude Anthropic), автоматически исключаются из "гонки", чтобы не ломать логику сортировки.

## 4. Архитектура Данных (Модель Аккаунта)
Финальная структура каждого аккаунта включает 4 линии таймеров и дополнительные метаданные:
1. **Gemini 3.1 Pro**
2. **Gemini 3 Flash**
3. **Claude 4.6 Opus/Sonnet**
4. **Claude Anthropic** (Полностью опциональный 4-й таймер):
   - Управляется встроенной галочкой в настройках (можно скрыть с главного экрана).
   - Позволяет выводить персональный настраиваемый бейдж на линии прогресс-бара (например, `Pro`, `Ultra`).
- Поля: **Страна** (ввод текста) и **Тип Аккаунта** (удобный селект из 3-х вариантов), которые выводятся в заголовке аккаунта.

## 5. Мобильная Сборка на Android (Cloud Build Architecture)
Для превращения React-сайта в мобильное приложение (без необходимости устанавливать Android Studio) мы спроектировали "Старую Схему" (DevOps подход):
1. **Bridge (Мост):** В проект добавлен Capacitor (`@capacitor/core`, `@capacitor/cli`, `@capacitor/android`). В папке `android/` сгенерирован полностью нативный проект `Gradle`.
2. **CI/CD Пайплайн (GitHub Actions):** Создан скрипт конфигурации `.github/workflows/android.yml`:
   - На каждый `git push` активируется сервер Ubuntu в облаке.
   - Устанавливаются `Node.js 22` и `Java 21`.
   - Запускается компиляция (`npm run build`).
   - Исходники веб-сайта синхронизируются в папку Android (`npx cap sync android`).
   - Запускается чистая компиляция Java/Kotlin (`./gradlew assembleDebug`).
   - Финальный файл `app-debug.apk` загружается в Artifacts.
3. Это решение позволило избежать долгой локальной настройки окружений, дало возможность скачивать приложение просто по клику на GitHub и сразу устанавливать на телефон!
